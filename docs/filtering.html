Filtering

Overview

The DataTable component provides comprehensive filtering capabilities including global search, column-specific filters, searchable select dropdowns, and additional filters for non-visible fields.

Filter Types

  • Global Search: Search across all searchable columns
  • Column Filters: Filter individual columns with different input types
  • Searchable Selects: Dropdown filters with search functionality
  • Additional Filters: Filter by non-visible fields like created_at

Global Search

Global search allows users to search across multiple columns simultaneously. 

<template>
  <DataTable
    :data="products"
    :columns="columns"
    :config="config"
    server-side
    @filter="handleFilter"
  />
</template>

<script setup>
const config = ref({
  filtering: {
    enabled: true,
    global: true,        // Enable global search
    debounce: 300       // Debounce delay in milliseconds
  }
})

// Handle global search
async function handleFilter({ key, value, type }) {
  if (key === 'global') {
    // Handle global search
    console.log('Global search:', value)
    // Send to server: ?search=value
  }
}
</script>

Column Filters

Each column can have its own filter with different input types based on the data type.

Filter Types

Text Filter

For text-based columns like names, descriptions

Searchable Select Filters

Select filters with search functionality that allow users to search through options locally before selecting a value.

Key Features

  • Search through dropdown options locally
  • Keyboard navigation (arrow keys, enter, escape)
  • Clear selection functionality
  • Server request only on selection, not during search
  • Visual feedback for selected options
// Searchable select configuration
{
  key: 'category',
  title: 'Category',
  filterable: true,
  filterType: 'select',  // This creates a searchable select
  placeholder: 'Filter Category...',
  filterOptions: [
    { value: '', label: 'All Categories' },
    { value: 'Electronics', label: 'Electronics' },
    { value: 'Home & Kitchen', label: 'Home & Kitchen' },
    { value: 'Books', label: 'Books' },
    { value: 'Sports', label: 'Sports' },
    { value: 'Toys', label: 'Toys' }
  ]
}

How It Works

  1. User clicks on the select filter dropdown
  2. Dropdown opens with search input and all options
  3. User types to search through options (local filtering)
  4. User selects an option by clicking or pressing Enter
  5. Server request is sent with the selected value
  6. Table updates immediately with filtered results

Server-Side Integration

Vue.js Event Handling

// Handle all filter events
async function handleFilter({ key, value, type }) {
  console.log('Filter applied:', { key, value, type })
  
  // Update filters state
  if (value === '' || value === null || value === undefined) {
    delete currentFilters.value[key]
  } else {
    currentFilters.value[key] = { value, type: type || 'contains' }
  }
  
  // Reset to first page when filtering
  paginationInfo.value.currentPage = 1
  
  // Fetch filtered data
  await fetchData()
}

// Build query parameters for API
function buildQueryParams() {
  const params = new URLSearchParams()
  
  // Add pagination
  params.append('page', paginationInfo.value.currentPage)
  params.append('per_page', paginationInfo.value.pageSize)
  
  // Add filters
  Object.entries(currentFilters.value).forEach(([key, filter]) => {
    if (filter.value) {
      params.append(`filter[${key}]`, filter.value)
      params.append(`filter_type[${key}]`, filter.type || 'contains')
    }
  })
  
  return params.toString()
}

Laravel Backend

private function applyFilters($query, Request $request)
{
    $filters = $request->get('filter', []);
    $filterTypes = $request->get('filter_type', []);
    
    foreach ($filters as $field => $value) {
        if (empty($value)) continue;
        
        $type = $filterTypes[$field] ?? 'contains';
        
        switch ($type) {
            case 'contains':
                $query->where($field, 'LIKE', "%{$value}%");
                break;
            case 'equals':
                $query->where($field, $value);
                break;
            case 'starts_with':
                $query->where($field, 'LIKE', "{$value}%");
                break;
            case 'ends_with':
                $query->where($field, 'LIKE', "%{$value}");
                break;
            case 'greater_than':
                $query->where($field, '>', $value);
                break;
            case 'less_than':
                $query->where($field, '<', $value);
                break;
            case 'date':
                $query->whereDate($field, $value);
                break;
        }
    }
    
    // Handle global search
    if ($globalSearch = $request->get('search')) {
        $query->where(function ($q) use ($globalSearch) {
            $q->where('name', 'LIKE', "%{$globalSearch}%")
              ->orWhere('description', 'LIKE', "%{$globalSearch}%");
        });
    }
}

API Parameters

The following parameters are sent to your API when filters are applied: 

# Global search
GET /api/products?search=laptop

# Column filters
GET /api/products?filter[name]=laptop&filter_type[name]=contains
GET /api/products?filter[category]=Electronics&filter_type[category]=equals
GET /api/products?filter[price]=100&filter_type[price]=greater_than

# Multiple filters
GET /api/products?filter[name]=laptop&filter_type[name]=contains&filter[category]=Electronics&filter_type[category]=equals

# Combined with pagination and sorting
GET /api/products?page=1&per_page=10&sort=name&direction=asc&filter[category]=Electronics&filter_type[category]=equals

Performance Tips

Debouncing

Text inputs are automatically debounced to prevent excessive API calls:

  • Text filters: 300ms debounce
  • Select filters: Immediate (no debounce needed)
  • Date filters: Immediate

Database Optimization

  • Add indexes on frequently filtered columns
  • Use full-text search for complex text filtering
  • Consider using database views for complex filters
  • Implement query caching for static filter options

Frontend Optimization

  • Local filtering for searchable selects
  • Automatic page reset when filtering
  • Loading states during filter operations
  • Clear filter functionality
