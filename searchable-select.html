Searchable Select Filters

Overview

Searchable Select filters provide an enhanced dropdown experience with local search functionality. Users can search through options before selecting, making it easy to find specific values in large option lists.

Key Features

  • Local search through dropdown options
  • Keyboard navigation (arrow keys, enter, escape)
  • Clear selection functionality
  • Server request only on selection, not during search
  • Visual feedback for selected options
  • Customizable placeholder text
  • Responsive design

How It Works

User Interaction Flow

  1. User clicks on the select filter dropdown
  2. Dropdown opens with search input and all options
  3. User types to search through options (local filtering)
  4. Options are filtered in real-time as user types
  5. User selects an option by clicking or pressing Enter
  6. Server request is sent with the selected value
  7. Table updates immediately with filtered results

Performance Benefits

  • No API calls during search: Search happens locally
  • Immediate feedback: Options filter as you type
  • Reduced server load: Only selection triggers requests
  • Better UX: Fast, responsive search experience

Custom Search Logic

The search is case-insensitive and matches anywhere in the label by default. You can customize this behavior by modifying the SearchableSelect component. 

// In SearchableSelect.vue - custom search logic
const filteredOptions = computed(() => {
  if (!searchQuery.value) return props.options
  
  return props.options.filter(option => {
    // Case-insensitive search in label
    return option.label.toLowerCase().includes(searchQuery.value.toLowerCase())
    
    // Alternative: Search in both value and label
    // return option.label.toLowerCase().includes(searchQuery.value.toLowerCase()) ||
    //        option.value.toLowerCase().includes(searchQuery.value.toLowerCase())
    
    // Alternative: Starts with search
    // return option.label.toLowerCase().startsWith(searchQuery.value.toLowerCase())
  })
})

Server-Side Integration

Event Handling

<template>
  <DataTable
    :data="products"
    :columns="columns"
    :config="config"
    server-side
    @filter="handleFilter"
  />
</template>

<script setup>
// Handle searchable select filter events
async function handleFilter({ key, value, type }) {
  console.log('Searchable select filter:', { key, value, type })
  
  // Update filters state
  if (value === '' || value === null || value === undefined) {
    delete currentFilters.value[key]
  } else {
    currentFilters.value[key] = { value, type: 'equals' } // Usually exact match for selects
  }
  
  // Reset to first page when filtering
  paginationInfo.value.currentPage = 1
  
  // Fetch filtered data from server
  await fetchData()
}

// Build query parameters
function buildQueryParams() {
  const params = new URLSearchParams()
  
  // Add filters
  Object.entries(currentFilters.value).forEach(([key, filter]) => {
    if (filter.value) {
      params.append(`filter[${key}]`, filter.value)
      params.append(`filter_type[${key}]`, filter.type || 'equals')
    }
  })
  
  return params.toString()
}
</script>

Laravel Backend

// Handle searchable select filters in Laravel
private function applyFilters($query, Request $request)
{
    $filters = $request->get('filter', []);
    $filterTypes = $request->get('filter_type', []);
    
    foreach ($filters as $field => $value) {
        if (empty($value)) continue;
        
        $type = $filterTypes[$field] ?? 'equals';
        
        // Searchable selects typically use exact matches
        if ($type === 'equals') {
            $query->where($field, $value);
        }
        // Handle other filter types as needed
    }
}

Best Practices

Option Management

  • Always include an "All" or empty option for clearing filters
  • Keep option labels clear and descriptive
  • Sort options alphabetically for better usability
  • Consider grouping related options
  • Limit options to reasonable numbers (< 100 for best performance)

User Experience

  • Use descriptive placeholder text
  • Provide visual feedback for selected options
  • Support keyboard navigation for accessibility
  • Show clear indication when no options match search
  • Make the clear/reset functionality obvious

Performance

  • Search happens locally - no API calls during typing
  • Only send server requests when user selects an option
  • Use debouncing if implementing server-side search
  • Consider virtual scrolling for very large option lists
  • Cache filter options when possible

Troubleshooting

Dropdown not opening

Check that:

  • filterType is set to 'select'
  • filterOptions array is provided and not empty
  • No CSS z-index conflicts

Search not working

Verify that:

  • Options have proper 'label' properties
  • Search input is receiving focus
  • filteredOptions computed property is working

Server not receiving filter

Ensure that:

  • @filter event handler is properly connected
  • Filter parameters are being built correctly
  • Server endpoint expects the correct parameter format
